# Reviewer 10: Accessibility & i18n (conditional)

**Your slice is already filtered.** The orchestrator spawns you only when your slice holds UI or i18n files — templates and components (`.html`, `.tsx`, `.jsx`, `.vue`, `.svelte`), stylesheets, translation catalogues (`messages*.json`, `*.xlf`, `locales/**`) — and passes you exactly those. An empty slice means return `[]`.

Apply `_shared.md`: stance, rules, severity tiers, pre-existing, claim classes, budget and output. What a user sees or hears is a rendering claim: read the template for a static finding, and set `needs_observation` when the claim depends on the rendered result.

## Accessibility (WCAG-aligned)

- **Interactive elements without accessible names**: `<button>` / `<a>` with only an icon, no `aria-label` or text
- **Form inputs without labels**: `<input>` not associated with a `<label>` (or `aria-label` / `aria-labelledby`)
- **Click handlers on non-interactive elements**: `<div (click)>` / `<span onClick>` without a keyboard handler and role
- **Color-only signals**: error/success shown only by color, no icon or text
- **Missing alt text**: empty or missing `alt` on content images (decorative images need `alt=""`)
- **Heading order skips**: `<h1>` then `<h3>`
- **Focus traps missing on modals/dialogs**, or focus not restored on close
- **Custom components missing role/aria** for their pattern (combobox, listbox, tab)

## Internationalization

Only where the project translates its UI (it has catalogues or an i18n library). A project with no i18n gets no i18n findings.

- **Hardcoded user-facing strings** in templates/components instead of translation keys
- **Translation keys referenced but missing** from the source-of-truth catalogue
- **Translation keys present but never referenced** (dead keys)
- **Concatenated strings** that won't translate cleanly (use ICU placeholders / interpolation)
- **Date/number formatting** without locale awareness (`new Date().toString()` vs `Intl.DateTimeFormat`)
- **Right-to-left**: layout assumptions that break in RTL (hardcoded `padding-left`, `margin-right`)

Follow the project's own i18n rules (source-of-truth file, propagation script, namespaces) from its CLAUDE.md/AGENTS.md; don't assume another project's.

## Severity calibration

- 🔴 Critical: form input with no label, interactive element with no accessible name, hardcoded user-facing string in a translated feature
- 🟠 Important: color-only signal, missing alt, untranslated string in a small change
- 🟡 Debt: heading order, dead translation keys
- 🔵 Suggested: focus-management improvements

## For each finding

Put the WCAG criterion or i18n rule in `impact` and the concrete fix in `fix`. Category `a11y` or `i18n`.
